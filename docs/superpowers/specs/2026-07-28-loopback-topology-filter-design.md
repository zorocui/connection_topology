# 拓扑环回连接过滤设计

## 背景

采集结果可能包含对端地址为 IPv4 环回地址（`127.0.0.0/8`）或 IPv6
环回地址（`::1`）的连接。当前拓扑将这些地址当作外部对端节点，因此会出现
服务器连接 `127.0.0.1` 或 `::1` 的“自己连接自己”节点。

## 目标

- 在设备模式和集群模式中隐藏所有环回连接。
- 同时处理新采集记录和已有历史记录。
- 保留数据库中的原始连接记录，不改变采集数量和历史审计数据。
- 不影响普通 IPv4、原生 IPv6、IPv4 映射 IPv6 及监听记录。

## 非目标

- 不删除或迁移数据库中的历史记录。
- 不在采集器写入阶段丢弃环回连接。
- 不隐藏设备连接自身业务 IP 的记录；本次仅过滤标准环回地址。
- 不改变采集详情、历史快照存储或设备连接测试行为。

## 方案

在共享地址工具中增加环回地址判断函数。该函数先复用现有 IP 地址归一化，
再使用标准 IP 地址解析判断 `is_loopback`：

- `127.0.0.1` 及整个 `127.0.0.0/8` 返回真。
- `::1` 返回真。
- IPv4 映射形式的环回地址（如 `::ffff:127.0.0.1`）归一化后返回真。
- 普通 IPv4、普通 IPv6 和无效地址返回假。
- `None` 返回假。

拓扑生成逻辑在聚合连接前调用该函数：

1. 设备模式 `build_topology` 跳过对端为环回地址的连接。
2. 集群模式 `build_cluster_topology` 跳过对端为环回地址的连接。
3. 对端为空的监听记录保持原有处理方式。
4. 数据库对象和连接记录不做修改。

## 数据流

采集器继续保存完整原始记录。页面请求拓扑时，后端读取连接记录，先进行地址
归一化，再判断是否为环回地址。环回连接不进入节点和边的聚合；其他连接按原有
规则生成拓扑响应。

## 测试

自动化测试覆盖：

- 设备模式隐藏 `127.0.0.1`。
- 设备模式隐藏其他 `127.x.x.x` 地址。
- 设备模式隐藏 `::1`。
- 设备模式隐藏 `::ffff:127.0.0.1`。
- 集群模式隐藏 IPv4 和 IPv6 环回连接。
- 普通外部 IPv4 和原生 IPv6 仍正常显示。
- 过滤过程不会删除或修改数据库连接记录。
