# 集群内部地址段更新冲突修复设计

## 问题

编辑已有集群时，如果保留现有内部 IPv4 地址段并增加新地址段，服务会把关系集合清空后重新插入全部地址段。SQLAlchemy 在同一次刷新中可能先执行插入、后执行删除，因此保留项会在旧记录尚存在时触发 `(cluster_id, cidr)` 唯一约束。

新建集群一次配置三个或更多地址段不受影响，配置上限仍为 100 个。

## 方案

采用差量更新：

- 标准化并校验提交的 CIDR；
- 保留数据库中仍然存在的地址段对象；
- 从关系集合移除已删除的地址段；
- 只为新增 CIDR 创建记录；
- 最后统一刷新事务。

该方案不修改接口、页面、数据表或配置上限，并减少不必要的数据库写入。

## 验证

- 编辑集群时从两个地址段增加到三个，且保留原有两项，保存成功；
- 再次提交相同地址段但改变输入顺序，不产生重复记录；
- 同一次编辑中删除旧项并新增新项，结果与提交内容一致；
- 原有 CIDR 格式、IPv4 限制、重复项和 100 项上限校验继续生效；
- 完整自动化测试、Python 静态检查和前端脚本检查通过。
