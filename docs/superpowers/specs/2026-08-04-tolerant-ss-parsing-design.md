# Linux ss 输出容错解析设计

## 背景

Linux 批量扫描通过 SSH 执行 `ss -H -tunap`，并逐行解析连接记录。当前解析器只要遇到一条非空但不足六列的输出，就会抛出 `parse_error`，导致该设备的整次扫描失败。内网连接变化较快，异常行无法稳定复现，因此修复应兼容瞬态或非标准输出，同时避免掩盖完整的命令或格式故障。

## 目标

- 单条或少量异常 `ss` 行不再导致整台设备扫描失败。
- 所有格式正确的 TCP/UDP 连接仍按现有规则入库。
- 被跳过的异常行数量通过扫描警告呈现，便于发现兼容性问题。
- 被跳过的异常原始行写入服务器应用日志，便于后续排查具体格式。
- 当非空输出中没有任何可解析的 TCP/UDP 连接时，扫描仍以解析错误失败。

## 解析行为

解析器逐行处理 `ss` 输出，并把结果分为三类：

1. 空行或明确不是 TCP/UDP 的行：忽略，不计为异常。
2. 格式正确的 TCP/UDP 行：按现有端点、状态、PID 和进程名规则转换为连接记录。
3. 以 TCP/UDP 开头但列数不足或端点无效的行：跳过并累计异常行数。

若至少解析出一条连接，扫描成功。存在异常行时，返回“已跳过 N 条无法解析的 ss 记录”警告；若采集命令因权限问题已产生降级警告，则合并两类警告，不覆盖任一信息。每条被跳过的异常候选行同时以警告级别写入服务器应用日志，日志包含设备 ID、`ss` 行号、异常原因和原始行内容。

若输出非空、包含 TCP/UDP 候选行，但最终没有解析出任何连接，并且至少有一条异常候选行，则抛出 `parse_error`。错误包含首条异常候选行的行号，但不包含原始行内容。

空输出表示当前没有匹配连接，继续视为成功并返回空连接集合。

## 代码结构

- 保留 `parse_ss_output(output)` 的公开行为，供现有调用方和测试使用。
- 新增内部解析结果，包含连接集合、跳过数量及首条异常行号。
- 为 `DeviceConnectionSpec` 增加可选设备 ID 上下文；扫描与导入测试调用方在已知 ID 时传入，SSH 连接行为不变。
- `LinuxCollector.collect()` 使用内部解析结果构造 `CollectionResult`，记录异常行日志，并合并权限降级与解析跳过警告。
- 解析单行的职责保持集中，避免在采集器中重复端点和协议判断。

## 日志与错误

- 单行异常的原始内容仅写入服务器应用日志，不写入数据库或返回给浏览器。
- 日志使用设备数据库 ID 标识来源，不记录 SSH 用户名、密码或其他凭据。
- 原始行可能包含内网地址、端口和进程信息，访问权限与保留周期沿用现有服务器日志策略。
- 全部候选行无效时继续使用 `parse_error`，并报告首条异常行号。
- SSH、命令超时和命令不可用等现有错误行为不变。

## 测试

新增自动化测试覆盖：

- 标准输出解析结果保持不变。
- 有效行与短行混合时保留有效连接并产生跳过警告。
- 有效行与无效端点行混合时保留有效连接并产生跳过警告。
- 每条异常候选行均记录设备 ID、行号、原因和原始内容。
- 未提供设备 ID 的直接采集调用仍可工作，并在日志中使用明确的未知设备标记。
- 非 TCP/UDP 的附加文本被忽略且不产生警告。
- 所有 TCP/UDP 候选行均无效时抛出带行号的 `parse_error`。
- 空输出成功返回空结果。
- 权限降级警告与解析跳过警告可以同时保留。

## 非目标

- 不自动重试 `ss` 命令。
- 不修改批量扫描队列、并发数或失败重试机制。
- 不尝试兼容无法识别其字段含义的全新 `ss` 输出格式。
