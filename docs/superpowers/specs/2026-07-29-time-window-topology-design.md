# 按时间范围查看连接拓扑——设计说明

## 1. 背景与目标

当前系统的设备拓扑和集群拓扑只展示各设备最近一次成功扫描得到的连接。为了排查短连接和已经断开的历史连接，需要在不触发新扫描的前提下，支持查看最近 1 天、3 天或 7 天内出现过的连接。

本功能的目标是：

- 默认保持现有行为，只展示当前连接。
- 支持选择“当前、1d、3d、7d”四种时间范围。
- 时间范围内已经断开的连接仍显示在拓扑中，并使用灰色连线。
- 同一对端下存在当前连接和历史连接时，拓扑仍只显示一条连线；只要其中存在当前连接，该连线就保持当前连接的颜色。
- 设备模式和集群模式使用一致的时间范围与连接状态规则。
- 避免临时本地端口或 PID 变化导致同一服务在历史拓扑中被拆成大量重复连接。

## 2. 范围

### 2.1 包含

- 设备拓扑接口增加时间范围参数。
- 集群拓扑接口增加时间范围参数。
- 服务维度的历史连接聚合。
- 当前连接与已断开连接的状态计算。
- 拓扑页面时间范围切换控件。
- 灰色历史连线、图例和连接详情。
- 相应的后端、前端及页面交互测试。

### 2.2 不包含

- 切换时间范围时自动发起设备扫描。
- 新建历史汇总表或修改现有扫描记录的存储结构。
- 展示任意自定义起止时间。
- 改变扫描历史的保留周期。
- 改变节点颜色来表达历史状态。
- 将监听端口纳入历史窗口；监听信息继续来自最近一次成功扫描。

## 3. 核心语义

### 3.1 当前连接

“当前连接”指设备最近一次成功扫描快照中的连接，不等同于页面打开时进行实时探测。

设备模式使用所选设备最近一次成功扫描；集群模式则分别使用每台设备各自最近一次成功扫描。接口返回快照时间，页面可据此判断当前数据是否陈旧。

### 3.2 时间窗口

- `current`：只使用最近一次成功扫描快照。
- `1d`：使用当前服务器时间向前 24 小时内的成功扫描快照。
- `3d`：使用当前服务器时间向前 72 小时内的成功扫描快照。
- `7d`：使用当前服务器时间向前 168 小时内的成功扫描快照。

无论最近一次成功扫描是否早于时间窗口，它始终作为该设备的当前基线被保留。若最近快照已早于窗口，则该设备只贡献当前基线，不额外引入更早历史。

只读取成功完成的扫描记录，失败、排队中或执行中的扫描不参与拓扑计算。

### 3.3 服务身份与去重

历史连接以“服务连接”而非原始套接字为单位聚合。服务身份由以下字段组成：

- 源设备
- 协议
- 归一化后的远端 IP
- 远端端口
- 进程名称

本地临时端口和 PID 不参与身份计算，以避免服务重连后产生大量重复边。空进程名应以统一值参与内部比较，但接口仍可返回空值。

每个聚合服务记录保留：

- 是否存在于当前基线
- 首次发现时间
- 最后发现时间
- 出现的成功扫描次数
- 观察到的本地 IP 集合
- 观察到的本地端口集合
- 观察到的 PID 集合
- 最新一次观察到的代表性连接信息

同一扫描内相同服务身份只计算一次观察次数。

### 3.4 连线状态

拓扑继续按“源节点—对端节点”聚合为一条边。

- 边中至少有一个聚合服务存在于当前基线：边为当前状态，使用现有正常颜色。
- 边中所有聚合服务都只存在于历史快照：边为已断开状态，使用灰色。

状态不属于服务身份的一部分。相同服务的当前观察结果会覆盖其历史断开表现，但历史首次发现、最后发现、观察次数、本地端口和 PID 集合仍予以保留。

边的连接数量表示聚合后的服务数量，而不是所有扫描快照中的原始套接字行数。接口可另外返回总观察次数，供详情展示。

## 4. 后端设计

### 4.1 接口

现有设备拓扑和集群拓扑接口增加可选查询参数：

```text
window=current|1d|3d|7d
```

参数缺省为 `current`，确保现有调用方和默认页面行为不变。非法值返回参数校验错误。

接口返回中增加或扩展以下信息：

- 请求使用的时间范围
- 各设备当前基线快照时间
- 聚合服务的当前/已断开状态
- 首次发现和最后发现时间
- 观察次数
- 观察到的本地地址、端口和 PID
- 边的当前服务数、历史服务数和总体状态

具体字段名在实现时应保持设备模式和集群模式一致，并尽量兼容现有前端字段。

### 4.2 查询与聚合流程

1. 查询目标设备最近一次成功扫描，建立每台设备的当前基线。
2. 当 `window` 不是 `current` 时，查询时间边界以内的成功扫描。
3. 将当前基线并入结果集并按扫描 ID 去重。
4. 对连接的本地和远端地址执行现有 IP 归一化。
5. 执行现有环回地址过滤，隐藏 `127.0.0.0/8`、`::1` 及映射后的环回连接。
6. 按服务身份聚合历史观察结果，并根据其是否出现在当前基线中计算状态。
7. 按源节点和对端节点进一步生成拓扑边。
8. 集群模式继续隐藏同一集群内设备之间的连接，只保留集群外部连接。

为避免一次性加载无关历史，数据库查询应限定目标设备、成功状态和最大 7 天时间范围，并使用已有的设备与扫描时间索引。

### 4.3 集群模式

集群模式按设备分别确定当前基线，因为不同设备最近一次成功扫描的时间可能不同。

服务身份仍包含源设备，避免不同设备访问同一远端服务时被错误视为同一个服务。生成集群级边时，再按照现有规则将源设备映射为集群节点并汇总。

同一集群内部的设备互联继续不显示。外部地址继续使用归一化后的 IPv4/IPv6 表示，避免 IPv4 映射 IPv6 与普通 IPv4 形成重复节点。

## 5. 前端设计

### 5.1 时间范围控件

在拓扑工具栏增加时间范围选择控件：

```text
当前 | 1d | 3d | 7d
```

默认选中“当前”。切换选项后：

- 保留当前设备、显示模式及其他已有筛选条件。
- 使用对应 `window` 参数重新请求当前模式的拓扑接口。
- 不触发设备扫描。
- 清除已失效的节点或连线聚焦状态。
- 使用现有加载状态和错误提示机制。

### 5.2 拓扑呈现

- 当前边沿用现有颜色和宽度规则。
- 仅包含历史服务的边显示为灰色。
- 混合边仍显示为当前颜色。
- 节点样式不因历史状态改变。
- 现有紧凑布局、聚焦、高亮、适配视图和重置功能保持不变。
- 图例增加“已断开连接”的灰色示例。

为了避免仅依赖颜色传达信息，连线详情和辅助文本必须明确标注“当前”或“已断开”。本次不额外引入虚线，以保持用户确认的灰色表达方案。

### 5.3 连接详情

连线详情按聚合服务展示：

- 状态：当前或已断开
- 协议
- 远端 IP 与端口
- 进程名称
- 首次发现时间
- 最后发现时间
- 出现次数
- 观察到的本地 IP 和端口
- 观察到的 PID

当同一边同时包含当前服务和历史服务时，详情分别标注每项状态；边本身仍为当前颜色。

## 6. 兼容性与异常处理

- 不传 `window` 时结果应与改造前的当前拓扑一致。
- 无成功扫描时沿用现有空状态。
- 时间窗口内无额外历史记录时，仅展示当前基线。
- 某设备当前基线早于时间窗口时，仍展示该基线，并返回其真实扫描时间。
- 历史记录中缺失进程名、PID 或本地地址时，不应阻断整张拓扑生成。
- 所有用户可见新增文案使用中文；`IP`、`PID`、`1d` 等专业缩写保留。
- 历史记录读取失败时，接口返回明确错误，页面保留当前错误提示体验，不展示部分误导性结果。

## 7. 测试方案

### 7.1 后端单元与接口测试

- `current` 默认值只使用最近一次成功扫描。
- `1d`、`3d`、`7d` 使用正确的小时边界。
- 当前基线早于时间窗口时仍被保留。
- 失败或未完成扫描不参与计算。
- 相同服务在多个快照中按服务身份合并。
- 本地临时端口或 PID 变化不会产生重复服务。
- 首次发现、最后发现和观察次数计算正确。
- 当前与历史混合时，服务和边均判定为当前。
- 全部只存在于历史时，边判定为已断开。
- 边的服务数和总观察次数口径正确。
- IPv4 映射 IPv6 继续归一化。
- 环回连接继续被隐藏。
- 集群内部连接继续被隐藏。
- 集群模式按设备分别选择当前基线。
- 非法 `window` 参数返回校验错误。
- 不传参数的接口响应保持向后兼容。

### 7.2 前端测试

- 页面存在“当前、1d、3d、7d”控件，默认选择“当前”。
- 切换范围时请求携带正确参数。
- 设备模式和集群模式均使用当前选择的时间范围。
- 已断开边应用灰色样式，混合边应用当前样式。
- 图例和详情使用中文状态文案。
- 切换时间范围后聚焦状态被正确清理。
- 空数据、请求失败和旧快照场景能够正确展示。

### 7.3 浏览器验收

- 在桌面宽度和较窄窗口下检查时间控件布局。
- 验证四个时间范围均可切换并刷新拓扑。
- 验证当前边、灰色历史边和混合边的视觉表现。
- 验证多连接情况下详情可读，原有紧凑布局操作正常。
- 检查浏览器控制台没有新增错误。

## 8. 验收标准

- 页面默认只显示最近一次成功扫描中的当前连接。
- 用户可选择 1d、3d、7d 查看对应时间段内出现过的全部服务连接。
- 已不在当前基线中的纯历史连线显示为灰色。
- 同一边只要包含当前服务，就不显示为灰色；详情能够区分其当前和历史服务。
- 临时本地端口和 PID 的变化不会造成拓扑边或服务详情大量重复。
- 设备模式和集群模式均符合相同规则。
- 现有环回过滤、地址归一化、集群内部连接隐藏和拓扑交互没有回归。
- 自动化测试通过，浏览器验收无新增控制台错误。
