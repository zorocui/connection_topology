# 集群内部 IPv4 地址段配置——设计说明

## 1. 背景与目标

Kubernetes 等集群通常存在 Pod、Service、网络插件或容器网络地址。这些地址可能无法直接匹配到受管设备，当前集群拓扑会将其识别为集群外部地址，造成外部节点和连线噪声。

本功能允许为每个集群手动配置多个内部 IPv4 CIDR。集群模式生成拓扑时，如果源设备访问的未受管远端地址落入源集群的内部地址段，则将该连接视为集群内部连接，不在拓扑中展示。

目标：

- 每个集群独立配置多个内部 IPv4 CIDR。
- 受管设备匹配优先，避免误隐藏真实的跨集群连接。
- 配置即时作用于当前和历史拓扑，不修改或删除原始连接记录。
- 将集群管理从设备管理页面拆出，建立与设备管理同级的独立页面。

## 2. 范围

### 2.1 包含

- 集群内部地址段的数据模型和数据库迁移。
- IPv4 CIDR 校验、规范化、去重和保存。
- 集群创建、查询、更新、删除接口对地址段的支持。
- 独立集群管理页面及主导航入口。
- 集群拓扑中的内部地址段过滤。
- 当前、1d、3d、7d全部时间窗口。
- 自动化测试、静态检查和浏览器验收。

### 2.2 不包含

- IPv6 CIDR。
- 全局共享地址段。
- 设备拓扑中的 CIDR 过滤。
- Excel 导入集群地址段。
- 自动发现 Kubernetes Pod CIDR 或 Service CIDR。
- 删除或修改已保存的连接历史。
- 为地址段配置名称、用途、优先级或启停状态。

## 3. 已确认的业务规则

### 3.1 配置范围

地址段按集群独立配置。一个集群可以配置零个或多个 IPv4 CIDR，例如：

```text
10.0.0.0/16
10.96.0.0/12
```

通过设备添加或 Excel 导入自动创建的集群，内部地址段默认为空。

### 3.2 生效模式

内部地址段仅在集群模式生效。设备模式继续展示完整连接，便于排查单机到 Pod、Service 或网络插件地址的通信。

规则在读取拓扑时实时应用，立即影响：

- 当前
- 1d
- 3d
- 7d

历史扫描和连接记录仍原样保存在数据库中。

### 3.3 受管设备优先

远端地址与受管设备的匹配优先于内部 CIDR：

- 唯一匹配到同一集群受管设备：按现有规则隐藏。
- 唯一匹配到其他集群受管设备：继续显示跨集群连接，即使其地址落入源集群配置的 CIDR。
- 同一地址匹配到多台受管设备：继续按现有规则作为外部地址显示并给出警告，不被内部 CIDR隐藏。
- 完全不匹配任何受管设备：检查源设备所属集群的内部 CIDR，命中后隐藏。

未分组设备没有内部地址段规则，保持现有拓扑行为。

## 4. 数据模型

### 4.1 新表

新增 `cluster_internal_networks`：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `id` | Integer | 主键 |
| `cluster_id` | Integer | 外键指向 `clusters.id`，不可为空，删除集群时级联删除 |
| `cidr` | String(18) | 规范化后的 IPv4 CIDR，不可为空 |

约束和索引：

- 唯一约束：`(cluster_id, cidr)`。
- `cluster_id` 普通索引。
- `Cluster.internal_networks` 与 `ClusterInternalNetwork.cluster` 建立双向关系。
- 删除集群时 ORM 和数据库外键均清理地址段。

### 4.2 数据库迁移

SQLite 迁移版本从 3 升级到 4。迁移必须幂等：

1. 如果表不存在则创建。
2. 创建唯一索引和 `cluster_id` 索引。
3. 记录 schema version 4。

现有集群无需回填，默认拥有空地址段列表。

## 5. CIDR 解析与校验

### 5.1 API 输入

集群创建和更新请求增加：

```json
{
  "name": "生产集群",
  "description": "核心业务",
  "internal_networks": [
    "10.0.0.0/16",
    "10.96.0.0/12"
  ]
}
```

缺省值为空列表。集群查询响应返回规范化后的字符串列表，并按网络地址和前缀长度稳定排序。

### 5.2 规范化规则

服务层使用：

```python
ipaddress.ip_network(value.strip(), strict=False)
```

规则：

- 去除首尾空白。
- 空字符串不保存。
- 只接受 `IPv4Network`。
- `10.0.1.5/16` 规范化为 `10.0.0.0/16`。
- 规范化后完全相同的 CIDR视为重复，整个请求失败。
- 合法但互相包含或重叠的 CIDR允许保存，不自动合并。
- 单个集群最多保存 100 个地址段，避免误提交无限列表。

错误响应使用中文，例如：

- `内部地址段不是合法的 CIDR：10.0.0.999/16`
- `内部地址段仅支持 IPv4：fd00:10::/64`
- `内部地址段重复：10.0.0.0/16`
- `单个集群最多配置 100 个内部地址段`

## 6. 服务与接口

### 6.1 集群服务

集群服务新增两个职责明确的函数：

- `normalize_internal_networks(values: list[str]) -> list[str]`
  - 负责解析、IPv4限制、规范化、重复检测和稳定排序。
- `replace_internal_networks(session, cluster, cidrs) -> None`
  - 在当前事务中用规范化结果替换集群地址段集合。

`create_cluster` 接受可选地址段列表。通过快速新建和 Excel 导入调用时不传地址段，行为保持不变。

### 6.2 集群 API

现有接口保持路径不变：

- `GET /api/clusters`
- `POST /api/clusters`
- `PUT /api/clusters/{cluster_id}`
- `DELETE /api/clusters/{cluster_id}`

变化：

- `ClusterCreate` 和 `ClusterUpdate` 增加 `internal_networks`。
- `ClusterRead` 增加 `internal_networks`。
- 创建和更新在一个数据库事务中保存集群属性和地址段。
- CIDR 任一项失败时整体回滚。
- 同名集群冲突、集群不存在等原有错误保持不变。

删除集群时：

- 设备变为未分组。
- 内部地址段级联删除。
- API 返回现有的 204。

## 7. 独立集群管理页面

### 7.1 路由和导航

新增：

```text
GET /clusters
```

主导航调整为：

1. 态势总览
2. 连接拓扑
3. 设备管理
4. 集群管理
5. 采集历史
6. 系统设置

设备管理页面删除原有的“已有集群”管理列表、重命名按钮和删除按钮，但保留：

- 设备所属集群选择。
- 快速新建集群。
- 扫描所选集群。
- Excel 导入中的所属集群。

### 7.2 页面布局

集群管理页面采用现有系统视觉语言：

- 左侧：新建或编辑表单。
- 右侧：集群列表。

表单字段：

- 集群名称。
- 描述。
- 内部 IPv4 地址段多行输入。

列表展示：

- 集群名称。
- 描述。
- 设备数量。
- 内部地址段标签。
- 编辑和删除操作。

点击编辑后将现有名称、描述和 CIDR 回填到表单。保存成功后刷新页面数据。取消编辑恢复新建状态。

### 7.3 输入拆分

页面允许用户使用以下方式分隔 CIDR：

- 换行。
- 英文逗号 `,`。
- 中文逗号 `，`。

前端只负责拆分和去除空项；后端负责最终校验和规范化。

删除确认文案明确说明：

```text
删除集群后，所属设备将变为未分组，内部地址段也会删除。确定继续吗？
```

## 8. 集群拓扑过滤

### 8.1 地址段预加载

构建集群拓扑时随集群一次性预加载 `internal_networks`，并为每个集群建立已解析的 `IPv4Network` 列表。禁止在每条连接循环内查询数据库。

### 8.2 过滤顺序

对每个已聚合服务连接：

1. 使用现有规则规范化远端 IP。
2. 环回地址已在服务聚合阶段过滤。
3. 查询 `address_owners[remote_ip]`。
4. 如果存在一个或多个受管设备所有者：
   - 唯一所有者时执行现有自身连接、同集群连接和跨集群连接规则。
   - 多所有者时保留现有冲突警告和外部地址展示。
   - 不检查内部 CIDR。
5. 如果没有受管设备所有者：
   - 源设备未分组：作为外部连接处理。
   - 远端不是 IPv4：作为外部连接处理。
   - 远端 IPv4 命中源集群任一内部 CIDR：跳过，不生成节点或边。
   - 未命中：作为外部连接处理。

地址段过滤发生在历史服务聚合之后、拓扑节点和边生成之前，因此当前和历史窗口使用同一规则。

### 8.3 设备模式

`build_topology` 不读取集群内部地址段，不改变设备模式结果。

## 9. Excel 导入兼容性

Excel 模板和导入列保持不变。`所属集群`：

- 匹配已有集群时使用其现有内部地址段。
- 自动创建新集群时地址段为空。
- 不从 Excel 创建或覆盖内部地址段。

## 10. 异常处理

- API 请求校验失败返回 422，并包含中文错误。
- 同名集群返回 409。
- 更新或删除不存在的集群返回 404。
- 地址段保存失败时事务回滚，原集群名称、描述和地址段保持不变。
- 拓扑读取到数据库中异常 CIDR 时不应导致整个页面崩溃；记录警告并忽略该条异常规则。正常情况下所有写入路径均会阻止异常 CIDR。

## 11. 测试方案

### 11.1 模型与迁移

- 新数据库包含 `cluster_internal_networks`。
- 旧版本数据库能够幂等升级到版本 4。
- 唯一约束有效。
- 删除集群级联删除地址段。

### 11.2 服务与 API

- IPv4 CIDR 正确规范化和排序。
- IPv6被拒绝。
- 非法 CIDR被拒绝。
- 规范化后重复被拒绝。
- 重叠 CIDR允许保存。
- 超过 100 个被拒绝。
- 创建、查询、更新返回 `internal_networks`。
- 更新失败时不保存部分修改。
- 快速创建和 Excel 自动创建集群时列表为空。

### 11.3 页面

- `/clusters` 可访问并包含创建、编辑、删除和 CIDR输入。
- 主导航包含同级“集群管理”。
- 设备管理页不再包含集群管理列表。
- 设备页的所属集群、快速新建、集群扫描和 Excel 导入不回归。
- CIDR 换行、英文逗号和中文逗号拆分正确。
- 错误信息使用中文。

### 11.4 拓扑

- 未受管远端命中源集群 CIDR时隐藏。
- 未命中时继续显示为外部地址。
- 同集群受管设备继续隐藏。
- 跨集群受管设备即使落入 CIDR仍显示。
- 多受管设备地址冲突即使落入 CIDR仍显示并产生警告。
- 未分组设备不应用 CIDR。
- IPv6远端不应用 IPv4 CIDR。
- 设备模式保持显示。
- `current`、`1d`、`3d`、`7d`均使用同一实时规则。
- 数据库连接记录未被删除或修改。

### 11.5 完整验收

- 全量 pytest。
- 全项目 Ruff。
- JavaScript 语法检查。
- 浏览器检查集群 CRUD、CIDR错误、设备页职责拆分和集群拓扑过滤。
- 桌面与窄屏布局检查。

## 12. 验收标准

- 用户能在独立集群管理页面为每个集群维护多个 IPv4 CIDR。
- 保存后 CIDR以规范形式返回并展示。
- 集群模式不再展示命中源集群内部 CIDR的未受管远端地址。
- 真实跨集群受管设备连接不会因 CIDR重叠而被隐藏。
- 修改规则后当前和历史时间窗口立即更新。
- 设备模式和原始历史数据不受影响。
- 原设备管理、Excel 导入和批量扫描流程无回归。
- 自动化测试和浏览器验收通过。
