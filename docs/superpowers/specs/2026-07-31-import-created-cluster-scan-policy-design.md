# Excel 自动创建集群的采集策略设计

## 问题

Excel 行可以同时填写“所属集群”和“采集间隔（分钟）”。当所属集群尚不存在时，当前实现先按默认值创建集群，采集间隔为 5 分钟，再让新设备继承集群策略。因此 Excel 中填写的 60 分钟被新集群的默认 5 分钟覆盖。

## 规则

- Excel 引用不存在的集群时，由第一条成功导入到该集群的设备记录初始化集群策略；
- 新集群的 `scan_interval_minutes` 使用该行“采集间隔（分钟）”；
- 新集群的 `scheduled_enabled` 使用该行“启用定时采集”；
- 创建该集群的设备以及后续属于同一集群的设备统一继承该集群策略；
- 如果同一 Excel 的后续行填写不同策略，仍以第一条成功创建集群的记录为准，避免同一次导入反复修改集群；
- Excel 引用已经存在的集群时，继续以已有集群策略为准，导入不能修改整个集群；
- 未填写所属集群的设备继续使用自身 Excel 设置。

## 实现

扩展 `create_cluster`，允许调用方在创建时传入采集间隔和定时采集开关，默认值仍保持 5 分钟和启用，因此其他创建入口行为不变。

`import_devices` 查找集群后：

1. 集群存在：直接使用现有集群；
2. 集群不存在：用当前行解析出的采集间隔和定时采集开关创建集群；
3. 继续通过现有 `cluster_scan_values` 计算设备最终策略。

同时更新 Excel 模板的字段说明，明确新建集群取首条记录策略、已有集群继承现有策略。

## 事务与错误

集群和设备继续在同一个逐行事务中创建。该行后续发生数据库错误时，事务回滚，新集群不会单独残留。格式错误仍按现有逐行隔离机制记录，不影响其他行。

## 测试

- 自动创建新集群时，Excel 填写 60 分钟且关闭定时采集，集群和设备均保存为 60 分钟、关闭；
- 同一新集群的后续行填写不同值时，设备继承首行建立的集群策略；
- 已存在集群仍覆盖 Excel 行设置；
- 未分组设备仍使用 Excel 行设置；
- 模板说明包含新集群和已有集群的策略优先级；
- 完整 pytest 和 Ruff 检查通过。

## 验收标准

当 Excel 首次导入一个不存在的集群并填写采集间隔 60 分钟时，导入后集群管理和设备管理均显示 60 分钟，后续定时采集按 60 分钟执行。
