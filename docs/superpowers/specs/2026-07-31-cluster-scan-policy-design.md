# 集群统一采集策略设计

## 目标

在集群管理中增加采集间隔和定时采集开关。集群策略是成员设备的统一执行策略：修改集群时立即覆盖全部当前成员，并作为以后加入该集群设备的默认值。

关闭定时采集只停止自动任务，不影响设备或集群的立即手动采集。

## 数据模型与迁移

`clusters` 表增加两个非空字段：

- `scan_interval_minutes`：整数，范围 1～10080，默认 5；
- `scheduled_enabled`：布尔值，默认启用。

数据库结构版本升级到 7。迁移现有集群时：

- 有成员设备的集群采用成员设备中出现次数最多的采集间隔；
- 若多个间隔出现次数相同，采用数值最小的间隔，保证迁移结果确定；
- 只有全部成员设备都已关闭定时采集时，集群才初始化为关闭；
- 没有成员设备的集群初始化为 5 分钟且启用定时采集。

设备表继续保存实际执行值，不引入可空继承字段。

## 集群创建与更新

集群创建、更新和读取接口增加：

- `scan_interval_minutes`；
- `scheduled_enabled`。

创建集群时保存设置。更新集群时在同一数据库事务中：

1. 更新集群名称、描述、内部地址段、历史保留策略和采集策略；
2. 批量更新当前全部成员设备的 `scan_interval_minutes` 与 `scheduled_enabled`；
3. 提交事务；
4. 提交成功后逐台调用调度服务同步任务。

任一数据库操作失败则整体回滚。调度同步发生在提交之后；单台同步异常要记录日志并继续同步其他设备，数据库中的设备值仍是下一次系统启动时重建任务的权威来源。

## 设备加入、导入与移出

设备新建、Excel 导入、快速新建集群以及设备更换所属集群时遵循以下规则：

- 指定已有集群时，忽略设备请求或 Excel 行中的采集间隔和定时开关，改用集群策略；
- 快速新建集群使用默认的 5 分钟、启用定时采集，设备随即采用该策略；
- 未指定集群时，继续使用设备自身提交的设置；
- 设备移出集群时保留最后一次同步到设备上的实际设置；
- 删除集群时，成员设备变为未分组，并保留删除前的采集间隔与定时开关；
- 设备加入另一个集群时立即采用目标集群策略。

Excel 模板字段保持不变。行内采集设置只对未分组设备生效。

## 调度同步

集群更新提交成功后，路由层获取成员设备并调用现有 `SchedulerService.sync_device`：

- 新间隔启用：使用新间隔新增或替换定时任务；
- 定时关闭：移除该设备已有任务；
- 调度服务未启用：只更新数据库，不执行运行时同步；
- 系统重启后，现有启动逻辑按设备表中的最终值恢复全部任务。

批量同步应使用已加载的成员设备，避免在循环内重复查询。

## 页面

集群管理表单新增：

- 采集间隔数字输入框，范围 1～10080，默认 5；
- “启用定时采集”开关，默认选中。

集群卡片显示：

```text
每 10 分钟采集 · 定时采集已启用
```

或：

```text
每 10 分钟采集 · 定时采集已关闭
```

设备管理页面中，属于集群的设备在周期信息旁显示“由集群统一管理”。不移除现有设备级字段与接口，因为未分组设备仍需要独立配置。

## 校验与错误处理

- 集群接口拒绝小于 1 或大于 10080 的采集间隔；
- 更新不存在的集群继续返回 404；
- 数据库批量更新与集群修改使用同一事务；
- 数据库提交失败时不执行调度同步；
- 调度同步异常记录设备 ID，不回滚已经提交的权威配置；
- 不增加第三方依赖，保持 Python 3.10。

## 测试与验收

自动化测试覆盖：

- 全新集群默认 5 分钟并启用定时采集；
- 版本 7 迁移按众数、最小值平局规则和全部关闭规则初始化集群；
- 集群更新同步全部成员且不影响其他集群和未分组设备；
- 启用、修改间隔、关闭时调度任务分别新增、替换和移除；
- 新建设备、Excel 导入及设备换组采用目标集群策略；
- 未分组设备保留自身提交值；
- 删除集群或移出集群后保留最后同步值；
- 页面表单、集群卡片和设备“由集群统一管理”提示；
- 全量测试、代码检查、浏览器验收及时间戳 Linux 打包。

现有数据的浏览器验收若需临时修改集群策略，必须在验收结束后恢复原值。不执行 Git 操作。
