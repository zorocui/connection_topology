# 服务器连接拓扑系统设计

## 1. 目标

构建一个基于 Python 3.10 的单管理员 Web 系统。管理员提供服务器地址、用户名和密码后，系统能够：

1. 通过 SSH 连接 Linux 服务器，通过 WinRM 连接 Windows Server。
2. 自动采集目标设备当前的 TCP/UDP 网络连接。
3. 保存每次采集的完整快照，并默认保留 30 天。
4. 在页面中以拓扑图为主展示服务器与对端之间的连接关系。
5. 支持手动采集及每台服务器独立配置的定时采集。
6. 加密保存远程登录密码，便于后续自动采集。

系统面向单机或可信内网中的单管理员场景，不包含平台用户登录、角色权限或多人协作功能。

## 2. 技术方案

采用 FastAPI 单体应用：

- Web 框架：FastAPI
- 服务端页面：Jinja2
- 局部页面交互：HTMX
- 拓扑渲染：Cytoscape.js
- ORM 与数据库：SQLAlchemy 2.x、SQLite
- 定时任务：APScheduler
- Linux 远程连接：Paramiko
- Windows 远程连接：pywinrm
- 凭据加密：cryptography 的 Fernet
- 测试：pytest、FastAPI TestClient
- Python：3.10

这一结构保持单进程、单数据库和简单部署，同时将采集器、解析器、调度器、持久化和页面展示划分为可独立测试的组件。

## 3. 系统架构

### 3.1 Web 层

FastAPI 同时提供 HTML 页面和内部 JSON 接口。页面包括：

- 总览
- 连接拓扑
- 设备管理
- 采集历史
- 系统设置

系统默认监听 `127.0.0.1`。管理员可通过配置显式改为内网地址。

### 3.2 设备管理

设备管理负责：

- 新增、编辑和删除服务器
- 保存设备名称、地址、系统类型、端口和用户名
- 测试 SSH 或 WinRM 连接
- 加密保存密码
- 配置每台设备的采集间隔
- 启用或停用定时采集
- 手动触发一次采集

编辑设备时不回显已保存密码。密码字段留空表示保留原密码，输入新值才会替换。

### 3.3 采集器

采集器按操作系统分为两个实现，共享统一接口：

- Linux 采集器通过 SSH 执行固定的只读 `ss` 命令，采集 TCP/UDP、本地与对端地址、端口、连接状态、PID 和进程名。若普通用户无权读取进程信息，则仍保存连接信息，并将 PID 和进程名置空。
- Windows 采集器通过 WinRM 执行固定 PowerShell 脚本，组合 `Get-NetTCPConnection`、`Get-NetUDPEndpoint` 与进程查询结果。

远程命令为系统内置常量，不拼接用户输入。连接和命令执行均设置超时。

### 3.4 标准化解析器

Linux 与 Windows 原始输出由各自解析器转换为统一连接结构：

- 协议：TCP 或 UDP
- 地址族：IPv4 或 IPv6
- 本地 IP
- 本地端口
- 对端 IP
- 对端端口
- TCP 状态；UDP 记录为空
- PID；权限不足或不可用时为空
- 进程名；权限不足或不可用时为空

对端名称可通过受控的反向 DNS 解析补充。系统不调用公网 IP 定位或资产识别服务，避免泄露内网地址。

### 3.5 调度器

APScheduler 按设备单独注册间隔任务，默认间隔为 5 分钟。设备配置变更后同步更新任务。

同一设备使用进程内互斥锁，避免手动采集与定时采集同时执行。一个设备的失败不会影响其他设备任务。

系统每天运行一次历史清理任务，删除超过保留天数的采集批次；连接记录通过级联关系一并删除。

## 4. 数据模型

### 4.1 Device

- `id`
- `name`
- `host`
- `os_type`：`linux` 或 `windows`
- `port`：Linux 默认 22，Windows 默认 5985
- `username`
- `encrypted_password`
- `scan_interval_minutes`：默认 5，必须大于等于 1
- `scheduled_enabled`
- `last_scan_status`
- `last_scan_at`
- `created_at`
- `updated_at`

同一主机地址、端口和用户名的组合必须唯一。

### 4.2 ScanRun

- `id`
- `device_id`
- `trigger_type`：`manual` 或 `scheduled`
- `status`：`running`、`success` 或 `failed`
- `started_at`
- `finished_at`
- `connection_count`
- `error_code`
- `error_message`

失败批次保存经过脱敏和长度限制的错误摘要。

### 4.3 ConnectionRecord

- `id`
- `scan_run_id`
- `protocol`
- `address_family`
- `local_ip`
- `local_port`
- `remote_ip`
- `remote_port`
- `state`
- `pid`
- `process_name`
- `remote_hostname`

索引覆盖采集批次、协议、状态、进程名和对端 IP，以支持拓扑与历史筛选。

### 4.4 SystemSetting

- `history_retention_days`：默认 30，必须大于等于 1

## 5. 数据流

### 5.1 新增设备

1. 管理员输入设备信息和密码。
2. 服务端校验主机、端口、用户名、系统类型和采集间隔。
3. 系统使用该凭据建立远程连接并执行最小只读探测。
4. 测试成功后，使用 Fernet 加密密码并保存设备。
5. 若启用定时采集，则为设备注册调度任务。

测试失败时不保存设备，也不记录明文密码。

### 5.2 执行采集

1. 手动请求或调度器触发采集。
2. 系统获取该设备互斥锁；若已有采集运行，则返回“正在采集”状态。
3. 创建状态为 `running` 的 `ScanRun`。
4. 解密凭据并调用对应操作系统的采集器。
5. 解析并校验全部结果。
6. 在单个数据库事务中写入连接记录，并将批次更新为 `success`。
7. 若连接、命令、解析或写入失败，则回滚连接记录并将批次更新为 `failed`。

失败批次不会产生不完整快照。页面继续展示该设备最后一次成功快照，并同时提示最近一次采集失败。

### 5.3 页面读取

拓扑页面默认读取选中设备最后一次成功批次：

- 中心节点代表服务器。
- 对端节点默认按对端 IP 聚合。
- 边显示该服务器与对端之间的连接数量。
- 点击节点或边后显示协议、端口、状态和本机进程明细。
- 可按设备、协议、状态和进程关键字过滤。

历史页面可按设备和时间查看批次，也可比较相邻两次成功批次。连接身份由协议、本地地址与端口、对端地址与端口、PID 和进程名组成，用于识别新增和消失连接。

## 6. 页面设计

整体采用“拓扑优先”的运维控制台布局，桌面端优先并适配常见平板宽度。

### 6.1 总览

显示：

- 已配置设备数与在线状态
- 最新成功快照中的活跃连接总数
- 最近 24 小时失败批次数
- 最近一次批次中新增和消失的连接数量
- 各设备最近采集时间与下次计划时间

### 6.2 连接拓扑

主区域为拓扑画布，侧边栏为设备及过滤器，详情抽屉展示选中节点或边的连接表。节点数量较多时按对端 IP 聚合，避免为每个端口生成独立节点。

### 6.3 设备管理

提供设备列表、连接状态、定时状态和操作菜单。新增与编辑表单包含连接测试。危险操作如删除设备需要二次确认。

### 6.4 采集历史

按设备、批次状态和时间范围筛选。成功批次可打开快照；相邻成功批次可查看新增与消失连接。

### 6.5 系统设置

当前版本仅提供历史保留天数设置，并解释清理行为。

## 7. 凭据与安全

- Fernet 主密钥通过环境变量 `APP_SECRET_KEY` 注入。
- `.env` 仅用于本地开发，并写入 `.gitignore`。
- 数据库只保存 Fernet 密文。
- 缺少或无法解析主密钥时应用拒绝启动。
- 日志不得输出密码、密文、Authorization 数据或完整远程异常对象。
- API 校验主机、端口、枚举值和数值范围。
- 远程命令由代码固定，不接受命令文本参数。
- SQLite 数据库文件不提交到版本控制。

由于当前版本是单管理员内网工具，应用自身不包含登录认证。若监听地址从本机改为内网，部署者必须使用反向代理访问控制或可信网络隔离。

## 8. 异常处理

系统区分并显示以下错误：

- DNS 或网络不可达
- 连接超时
- SSH 或 WinRM 认证失败
- WinRM 未启用或协议配置不兼容
- 远程命令不可用
- 权限不足导致进程信息缺失
- 输出格式无法解析
- 数据库写入失败
- 设备已有采集任务运行

权限不足但仍能取得网络连接时，批次记为成功并显示警告。无法获得可解析连接数据时，批次记为失败。

## 9. 测试策略

### 9.1 单元测试

- Linux `ss` 输出：IPv4、IPv6、TCP、UDP、监听状态、已连接状态、带与不带进程信息。
- Windows PowerShell 输出：TCP、UDP、无属主进程、IPv4 和 IPv6。
- Fernet 密码加解密、错误密钥和空密钥启动失败。
- 日志脱敏。
- 拓扑聚合与相邻批次差异计算。

### 9.2 集成测试

- 设备新增、编辑、删除和连接测试接口。
- 成功采集的事务写入。
- 失败采集不产生部分连接记录。
- 手动与定时采集互斥。
- 历史保留清理。
- 页面和 JSON 接口返回正确数据。

SSH 与 WinRM 在自动化测试中使用模拟客户端，不依赖真实远程服务器。

### 9.3 页面流程测试

验证以下关键流程：

1. 新增 Linux 或 Windows 设备并测试连接。
2. 手动触发采集并查看状态。
3. 打开拓扑并筛选连接。
4. 查看历史批次和连接差异。
5. 修改保留天数。

## 10. 项目与运行环境

- 在项目根目录使用 Python 3.10 创建 `.venv`。
- 提供依赖锁定文件、`.env.example`、数据库初始化和启动命令。
- 提供中文 README，说明 Windows 本机开发、SSH/WinRM 前置条件、密钥生成、启动与测试方式。
- 初次启动自动创建 SQLite 表和默认设置。

## 11. 验收标准

满足以下条件即视为完成：

1. 可新增 Linux/SSH 与 Windows/WinRM 设备，并成功测试连接。
2. 密码以 Fernet 密文保存，日志和页面均不回显密码。
3. 可手动采集，也可按每台设备独立分钟间隔自动采集。
4. 可保存成功与失败批次，并保留每次成功采集的完整连接快照。
5. 可在拓扑页面查看服务器、对端 IP 和连接明细。
6. 可筛选历史并比较相邻成功批次的新增与消失连接。
7. 默认清理 30 天前历史，且可在设置中修改。
8. Linux 权限不足时能降级采集，Windows 能通过 WinRM 采集 TCP/UDP。
9. 自动化测试不依赖真实服务器并全部通过。
10. 项目在 Python 3.10 的 `.venv` 中可安装并运行。
