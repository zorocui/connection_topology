# 历史拓扑 SQL 聚合性能优化设计

## 背景

内网环境约有十几台设备，`1d` 时间范围内已经产生约 137 万条原始连接。
当前历史拓扑会把时间范围内的所有成功快照及其连接记录加载为
SQLAlchemy/Python 对象，再在 Python 中逐条归一化和聚合。该流程占用大量内存，
容易触发交换区，页面会长期停留在“正在聚合”。

本次采用方案 A：由 SQLite 即时完成历史连接的筛选和分组，Python 只处理聚合
结果。统计结果必须完全精确，并保持当前拓扑语义。

## 目标

- 约 137 万条 `1d` 原始连接的首次查询在参考环境中不超过 10 秒。
- `1d`、`3d`、`7d` 不再实例化全部 `ConnectionRecord` 对象。
- 保持首次发现、最后发现、出现次数、当前/已断开状态、端口、PID 和进程信息
  的现有含义。
- 保持 IPv4 映射地址归一化、回环连接隐藏、集群内部连接隐藏、集群内部地址段
  隐藏和跨集群连接聚合规则。
- 设备模式与集群模式共同使用新的历史聚合服务。
- 历史请求失败或超过前端等待时间时显示明确提示，不无限停留在加载状态。

## 不在本次范围

- 不新增持久化的连接汇总表。
- 不采用快照采样或近似统计。
- 不修改采集协议、采集周期或原始连接保存格式。
- 不删除或压缩现有历史数据。
- 不更换 SQLite 数据库。
- 不使用 Git。

## 方案对比

### 采用：SQLite 即时聚合

数据库使用过滤、分组、最小值、最大值和去重集合完成主要计算。Python 对数量
较小的分组结果执行 IP 归一化合并和拓扑节点映射。该方案不需要历史数据回填，
升级后立即生效。

### 未采用：持久化汇总表

查询速度最快，但需要新增数据表、旧数据回填、采集事务同步和汇总修复机制，
本次范围过大。

### 未采用：历史采样

实现简单，但会使出现次数和首次、最后发现时间不精确，不符合要求。

## 数据访问架构

### 当前范围

`window=current` 保持现有最新成功快照逻辑。当前范围只加载每台设备最新成功
快照及其连接，不进入历史 SQL 聚合路径。

### 历史范围

新增独立的历史服务查询，输入：

- 设备 ID 集合；
- `1d`、`3d` 或 `7d`；
- 各设备当前成功快照 ID；
- 可选目标集群范围。

查询连接 `scan_runs` 与 `connection_records`，只读取：

- 时间下限内的成功快照；
- 每台设备最新成功快照，即使该快照因时钟边界略早于时间下限；
- `remote_ip` 非空的连接。

SQLite 首先按原始服务键分组：

- 源设备 ID；
- 协议；
- 原始对端 IP；
- 对端端口；
- 进程名。

每组返回：

- 最早和最晚快照时间；
- 去重后的快照 ID；
- 去重后的本地 IP、本地端口和 PID；
- 是否存在于当前快照；
- 最新一条代表记录的状态、地址族、端口、PID、进程名和对端主机名。

Python 只对这些分组结果执行：

- `::ffff:x.x.x.x` 等地址归一化；
- 归一化后相同服务键的二次合并；
- 快照 ID 集合并集，以保持出现次数完全精确；
- 本地 IP、端口和 PID 集合并集；
- 使用最晚记录作为展示代表值。

二次合并的数据量由“不同连接组合数”决定，不再与 137 万条原始记录线性对应。

## 目标集群查询

前端集群请求增加 `cluster_id`：

```text
/api/topology/clusters?window=1d&cluster_id=12
```

后端验证集群存在，并构造目标集群成员的已解析地址集合。历史候选数据包括：

- 目标集群成员作为源设备发出的所有连接；
- 其他受管设备连接到目标集群成员地址的入向连接。

聚合完成后仍使用现有地址所有权和集群规则构建拓扑，并在服务端裁剪为：

- 目标集群节点；
- 与目标集群直接相连的边；
- 上述边的另一端节点。

如果地址同时属于多台设备，继续按外部地址处理。候选查询可以多读该地址的少量
记录，但最终不得错误映射为目标集群。

`window=current` 也接受 `cluster_id` 并返回目标一跳子图，减少传输量；其连接数据
仍来自各设备最新成功快照。

## 索引与旧数据库迁移

模式定义和幂等迁移同时增加：

```text
scan_runs(device_id, status, started_at)
connection_records(scan_run_id, remote_ip, remote_port, protocol, process_name)
```

迁移版本递增。应用启动时使用 `CREATE INDEX IF NOT EXISTS`，确保已有内网数据库
自动获得索引，不需要人工重建数据库。

保留现有索引，避免影响其他查询；确认新联合索引投入使用后再考虑单独清理冗余
索引，本次不删除索引。

## 缓存

增加进程内、线程安全、最长 30 秒的历史拓扑缓存：

- 键包含模式、目标设备或集群、时间范围；
- 只缓存 `1d`、`3d`、`7d`，不缓存 `current`；
- 返回缓存值前复制或序列化隔离，调用方不得修改缓存原对象；
- 扫描成功、设备变更、设备删除、集群变更和内部地址段变更时清空缓存；
- 多进程部署时每个进程独立缓存，最坏陈旧时间不超过 30 秒。

缓存用于改善刷新和多人重复查看；137 万条首次查询的 10 秒目标不能依赖缓存。

## API 与前端错误处理

- `cluster_id` 不存在时返回 HTTP 404 和中文错误信息。
- 非法时间范围继续由现有类型校验返回 HTTP 422。
- 前端使用 `AbortController`，历史请求等待超过 15 秒后停止等待并显示：
  “历史拓扑计算超时，请稍后重试或缩短时间范围。”
- 用户切换目标、模式或时间范围时取消上一个未完成请求，防止旧响应覆盖新选择。
- 后端异常不得返回部分拓扑；页面清除旧图并显示失败状态。
- 前端取消只结束浏览器等待。SQLite 查询是否中断由执行环境决定，因此性能目标
  仍通过 SQL 聚合本身保证。

## 代码边界

- `app/services/topology_history.py`
  - 负责当前快照 ID 查询；
  - 负责 SQL 历史聚合；
  - 返回与现有 `aggregate_service_connections` 相同的服务字典结构。
- `app/services/topology.py`
  - 继续负责设备、地址和集群到节点、边的映射；
  - 接受已聚合服务，不读取历史原始连接；
  - 提供目标集群一跳裁剪。
- `app/routes/api.py`
  - 解析并验证 `cluster_id`；
  - 选择当前或历史数据路径；
  - 使用历史缓存。
- `app/services/topology_cache.py`
  - 提供小型线程安全 TTL 缓存及统一失效接口。
- `app/migrations.py`、`app/models.py`
  - 声明并迁移联合索引。
- `app/static/js/topology.js`
  - 发送 `cluster_id`；
  - 取消旧请求；
  - 提供 15 秒超时和中文提示。

## 兼容性

- API 返回结构保持 `nodes`、`edges`、`connections`、`warnings` 等现有字段。
- 连接详情继续包含首次发现、最后发现、出现次数、本地 IP、本地端口和 PID。
- 北京时间显示、当前与历史连线颜色、协议/状态/进程前端筛选保持不变。
- 现有数据库升级不修改原始记录。
- Python 版本仍为 3.10，不新增第三方依赖。

## 测试

### 结果一致性

使用小型固定数据集，同时运行旧 Python 聚合和新 SQL 聚合，逐字段比较：

- 服务键；
- 当前/断开状态；
- 首次、最后发现；
- 出现次数；
- 本地 IP、端口和 PID 集合；
- 最新代表记录；
- IPv4 映射地址合并；
- 同一扫描内重复连接不重复增加出现次数。

### 集群语义

- 目标集群的出向连接保留；
- 其他集群到目标集群的入向连接保留；
- 同集群连接隐藏；
- 无关集群之间的连接不返回；
- 未受管外部地址保留；
- 集群内部地址段隐藏；
- 重复地址所有权继续按外部地址处理。

### 迁移与缓存

- 旧数据库能够幂等创建两个联合索引；
- 重复启动不会报错；
- 缓存命中不重复聚合；
- 扫描和配置修改会使缓存失效；
- TTL 到期后重新计算。

### 性能

提供独立基准脚本，在临时 SQLite 数据库生成约 137 万条连接记录：

- 基准数据不写入正式数据库；
- 计时不包含数据生成；
- 冷缓存执行 `1d` SQL 聚合；
- 参考环境目标小于等于 10 秒；
- 记录原始行数、聚合组数、查询耗时和峰值内存；
- 基准结束后删除临时数据库。

完整 pytest、Ruff、JavaScript 语法检查和浏览器交互验收必须通过。

## 部署与回退

- 启动迁移只新增索引，首次创建索引可能短暂占用 SQLite 写锁；建议在停止采集服务
  后升级并首次启动。
- 发布包继续使用带时间戳文件名。
- 若新历史查询异常，可回退到上一版本程序；新增索引不会阻止旧版本读取数据库。
- 部署包不包含内网生产数据库，升级前仍建议备份
  `connection_topology.db`。
