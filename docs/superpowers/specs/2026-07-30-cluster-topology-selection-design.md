# 集群拓扑按目标加载设计

## 背景与目标

当前点击“集群模式”后，页面会立即请求并绘制所有集群的拓扑。集群筛选只在
前端重绘时生效，右侧详情仍保留全局集群拓扑的空连接列表，因此选择集群后会
出现“当前筛选条件下没有连接”的误导提示。

本次改造使集群模式与设备模式保持一致：用户先选择目标集群，页面再加载和显示
拓扑。选中集群后，右侧默认显示简要概览，详细连接仍通过点击节点或连线查看。

## 交互设计

### 进入集群模式

- 清空设备模式遗留的拓扑数据和右侧详情。
- 显示集群选择框，不自动请求 `/api/topology/clusters`。
- 画布空态标题为“等待选择目标集群”。
- 空态说明为“选择集群后显示该集群与外部节点的连接关系。”
- 快照说明提示“选择集群后显示其连接拓扑”。

### 选择目标集群

- 选择非空集群后，请求现有 `/api/topology/clusters?window=...` 接口。
- 加载期间显示“正在读取集群拓扑”及当前时间范围说明。
- 前端仅保留：
  - 目标集群节点；
  - 与目标集群直接相连的边；
  - 上述边另一端的集群、独立设备或外部地址节点。
- 不显示其他无关集群和连接。

### 右侧概览

集群加载完成后，右侧默认显示：

- 标题：目标集群名称；
- 成员设备数；
- 当前筛选条件下的外部连接组数；
- 引导语：“点击拓扑中的节点或连线查看详细信息。”

右侧默认概览不调用连接明细表渲染函数，因此连接数为零时不再显示
“当前筛选条件下没有连接”。

用户点击节点或连线后，继续沿用现有详情展示：

- 点击集群节点：显示成员设备和该节点相关的连接明细；
- 点击其他节点：显示节点连接明细；
- 点击连线：显示该组连接的协议、端口、状态和进程明细。

### 无连接和异常状态

- 目标集群存在但没有任何外部连接时：
  - 画布显示目标集群节点；
  - 右侧概览显示成员数和“0 组外部连接”；
  - 不显示错误或“当前筛选条件下没有连接”。
- 原始拓扑有连接，但协议、状态或进程筛选后为零时：
  - 保留目标集群节点；
  - 右侧概览实时更新为“0 组外部连接”；
  - 不用覆盖式空态遮挡目标集群节点。
- 接口请求失败时：
  - 销毁旧图并清空旧数据；
  - 显示“集群拓扑加载失败”及接口错误信息；
  - 右侧恢复“选择连接”的引导状态。
- 集群下拉框恢复为空时，清空拓扑并回到等待选择状态。

## 状态与数据流

页面继续使用现有 `mode`、`source`、`graph` 状态，并新增明确的集群选择流程：

1. 切换到集群模式时只重置状态，不调用加载接口。
2. 集群选择框变化时：
   - 空值：调用集群等待状态重置；
   - 有值：调用集群加载函数。
3. 时间范围变化时：
   - 设备模式按现有逻辑加载设备；
   - 集群模式只有已选择集群时才重新加载。
4. 协议、状态和进程筛选变化时：
   - 重新计算目标集群子图；
   - 重绘拓扑；
   - 同步更新右侧默认集群概览，除非用户刚选择了具体节点或连线。

为避免保留过期详情，任何模式切换、目标变更或重新加载都会先恢复默认右侧状态。

## 实现边界

- 复用现有全局集群拓扑 API，不修改数据库、模型或后端聚合规则。
- 本次只改变请求触发时机、前端子图筛选和右侧默认状态。
- 不增加多选集群、集群比较、拓扑缓存或新的后端分页接口。
- 继续遵循现有时间范围、当前连接与历史断开连接的显示规则。

## 测试与验收

### 自动化测试

- 集群模式切换不会立即调用集群拓扑加载函数。
- 未选择集群时，时间范围变化不会发起集群请求。
- 集群选择变化由绘图改为加载；空值恢复等待状态。
- 集群子图只包含目标集群及其直接连接。
- 默认右侧概览包含集群名称、成员数和连接组数，且不调用空连接明细提示。
- 无连接和筛选后零连接时保留目标集群节点，并在右侧正确显示零连接概览。
- JavaScript 语法检查和完整 Python 测试套件通过。

### 浏览器验收

- 点击“集群模式”后网络与画布保持等待状态。
- 选择集群后才显示拓扑。
- 右侧显示所选集群概览，不出现误导性的“当前筛选条件下没有连接”。
- 时间范围和协议、状态、进程筛选行为正确。
- 切换回设备模式后设备选择流程不受影响。
- 浏览器控制台无新增错误。
