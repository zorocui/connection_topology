# 设备模式目标设备筛选设计

## 目标

在拓扑页的设备模式中，“目标设备”下拉框只显示可执行采集的设备，不显示仅用于集群标注的设备。仅标注设备仍须在集群模式及拓扑关系中正常显示。

## 现状

`/topology` 页面当前查询全部 `Device`，按名称排序后交给模板生成目标设备选项。设备是否可采集由 `Device.collection_enabled` 表示；值为 `False` 时，该设备仅用于集群标注。

## 方案

在 `/topology` 页面路由生成 `devices` 模板上下文时，将查询条件限定为 `Device.collection_enabled.is_(True)`，并保留现有名称排序。模板、设备 API、数据库模型和拓扑生成服务均不修改。

选择在服务端页面查询处过滤，是因为该查询结果只服务于设备模式的目标设备下拉框。这样不会把无效候选项传入模板，也不会影响集群列表或拓扑数据中仅标注设备的展示。

## 数据流

1. 用户打开 `/topology`。
2. 页面路由查询 `collection_enabled=True` 的设备并按名称排序。
3. 模板使用查询结果生成“目标设备”下拉选项。
4. 集群筛选项继续通过独立的 `Cluster` 查询生成。
5. 用户选择设备或集群后，现有拓扑 API 和前端绘图流程保持不变。

## 边界行为

- 没有可采集设备时，下拉框只显示“选择一台设备”的占位选项。
- 仅标注设备不会成为设备模式的主动筛选目标。
- 仅标注设备仍可作为集群成员或拓扑关联节点出现。
- 正常采集设备的显示文本和排序不变。

## 测试

新增页面路由测试，创建一台 `collection_enabled=True` 的正常设备和一台 `collection_enabled=False` 的仅标注设备，然后请求 `/topology`，验证：

- 正常设备出现在目标设备下拉框中；
- 仅标注设备不出现在目标设备下拉框中；
- 集群模式入口与目标集群筛选仍然存在。
