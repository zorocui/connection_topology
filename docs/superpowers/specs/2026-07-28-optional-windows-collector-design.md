# Windows 采集组件可选化设计

## 目标

在未安装 `pywinrm` 的内网环境中，系统必须正常安装和启动，Linux SSH
扫描、页面、定时任务及已有数据功能不受影响。Windows 扫描作为可选能力，
缺少组件时不得造成模块导入失败或启动阻塞。

## 依赖设计

- 从项目默认依赖中移除 `pywinrm`。
- 新增 `windows` 可选依赖组，包含 `pywinrm>=0.5,<1`。
- 基础环境使用 `pip install -e .`；需要 Windows 扫描时使用
  `pip install -e ".[windows]"`。

## 运行时设计

- Windows 采集模块对 `winrm` 使用受控可选导入。
- 无论是否安装 `pywinrm`，`WindowsCollector` 类都可以安全导入和实例化。
- 缺少组件时，Windows 连接测试和正式采集均立即抛出统一的采集器错误，
  中文消息为“当前环境未安装 Windows 采集组件，请安装 pywinrm”。
- Linux 采集器、应用启动和调度器不读取或调用 `winrm`，因此继续正常工作。
- Windows 设备仍可添加或通过 Excel 导入；其后台连接测试记录为失败，
  设备数据本身保留。

## 错误与页面行为

- 错误使用现有 `CollectorError` 通道返回，不输出 Python 导入堆栈。
- API 和页面沿用现有错误展示逻辑，向用户显示中文缺失组件提示。
- 不自动安装依赖，不访问互联网，也不在启动阶段反复重试。

## 测试

- 模拟 `pywinrm` 不可用，验证 Windows 采集模块仍能导入。
- 验证缺少组件时 Windows 测试和采集返回预期错误码及中文消息。
- 验证应用可创建并启动，Linux 采集器不受影响。
- 运行现有完整测试和静态检查，防止已有功能回归。
