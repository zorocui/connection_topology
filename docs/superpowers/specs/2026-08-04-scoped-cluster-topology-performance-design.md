# 目标集群拓扑提前裁剪性能优化设计

## 背景

集群模式选择目标集群后，前端请求 `/api/topology/clusters` 并在 15 秒后中止等待。当前时间范围也发生超时，且设备主机地址均为纯 IP，因此主要瓶颈不是 DNS，而是后端在目标集群查询中仍读取和聚合大量无关连接。

当前模式会加载所有设备的最新成功快照及其全部连接，构建全局节点和边后才裁剪为目标集群的一跳子图。历史模式已经增加目标集群条件，但把目标成员出向连接与其他设备入向连接放在同一个 `OR` 条件中；现有历史联合索引以 `scan_run_id` 开头，无法高效覆盖从 `remote_ip` 反查目标集群入向连接的路径。

## 目标

- `current`、`1d`、`3d`、`7d` 的目标集群请求都在读取连接记录前完成范围裁剪。
- 保留目标集群成员发出的所有有效出向连接。
- 保留其他受管设备指向目标集群成员地址的入向连接。
- 不读取或聚合与目标集群无直接关系的连接记录。
- API 返回结构、集群内部连接隐藏、内部 CIDR 隐藏、IPv4 映射地址归一化和一跳裁剪语义保持不变。
- 保留前端 15 秒超时，不通过延长等待时间掩盖后端性能问题。

## 查询架构

### 共享准备阶段

`build_cluster_topology()` 继续读取设备和集群元数据，用于节点名称、成员列表、地址所有权和内部网络规则。它只加载每台设备最新成功扫描的元数据，不预加载连接关系。

当提供 `target_cluster_id` 时，系统提前计算：

- 目标集群成员设备 ID；
- 目标成员规范化后的 IP 地址；
- 目标成员 IPv4 地址对应的 `::ffff:` 映射形式；
- 每台设备最新成功扫描 ID。

这些值共同形成目标集群连接候选范围。

### 当前范围

新增当前快照连接聚合入口。查询仅访问最新成功扫描，并将候选拆为两条可独立使用索引的路径：

1. 出向路径：源设备属于目标集群成员；
2. 入向路径：连接的 `remote_ip` 属于目标成员地址集合。

两条路径按连接记录 ID 去重后合并。Python 只对候选记录执行现有服务键聚合、IP 规范化和当前状态构造，不再实例化所有设备最新扫描中的无关连接。

未提供 `target_cluster_id` 的内部调用继续支持全局当前拓扑，保持现有行为。

### 历史范围

历史聚合保留时间窗口、成功扫描和每台设备最新快照边界。目标集群查询不再使用单个出向/入向 `OR` 条件，而是构造两条候选连接 ID 查询：

1. 出向候选按目标成员设备与时间范围筛选；
2. 入向候选先按目标成员 `remote_ip` 筛选，再验证扫描状态和时间范围。

候选 ID 使用 SQL `UNION` 去重，随后进入现有精确分组聚合。首次发现、最后发现、出现次数、当前状态、本地 IP、端口、PID 和最新代表记录的计算方式不变。

## 索引与迁移

在模式声明和幂等迁移中增加：

```text
connection_records(remote_ip, scan_run_id)
```

该索引用于目标集群入向路径从少量成员地址反查连接，再关联最新扫描或历史有效扫描。保留现有 `scan_run_id` 开头的索引，为出向路径和其他拓扑查询服务。

迁移版本递增。旧数据库启动时使用 `CREATE INDEX IF NOT EXISTS` 自动创建索引，不修改或回填原始连接数据。

## 拓扑构建

候选服务进入现有节点与边映射逻辑后，仍执行：

- 同设备和同集群连接隐藏；
- 集群内部 CIDR 地址隐藏；
- 多设备地址冲突按外部地址处理；
- IPv4 映射地址归一化；
- 只返回目标集群、与其直接相连的边及一跳对端节点。

提前裁剪只减少输入数据，不改变最终展示规则。前端保留现有二次一跳过滤作为防御性处理。

## 缓存与并发

历史拓扑继续使用现有 30 秒缓存及扫描成功后的统一失效。当前拓扑不新增缓存，以免改变实时快照语义。浏览器取消请求仍只停止客户端等待；本次通过减少数据库工作量降低后端查询在取消后继续占用资源的概率。

## 错误处理

- 不存在的目标集群继续返回 HTTP 404。
- 非法时间范围继续返回 HTTP 422。
- 查询异常不返回部分拓扑。
- 前端继续在 15 秒后显示加载失败；错误文案不在本次性能优化中调整。

## 测试

### 结果语义

- 当前目标集群保留目标成员的出向连接。
- 当前目标集群保留其他集群到目标成员的入向连接。
- 当前目标集群排除无关集群之间的连接。
- 历史目标集群保持相同的出向、入向和排除语义。
- 同一连接同时满足出向和入向条件时只计算一次。
- IPv4 映射、同集群隐藏、内部 CIDR 与多地址所有者行为保持不变。

### 查询范围与性能

- 构造少量目标连接和大量无关当前连接，断言当前聚合入口只返回目标候选。
- 构造少量目标连接和大量无关历史连接，断言历史聚合结果不包含无关候选。
- 使用 SQLite 查询计划或可观察的候选计数验证入向路径可使用 `remote_ip` 前导索引。
- 现有历史基准测试继续通过；新增目标集群范围基准，证明运行时间主要随目标候选量增长，而不是随全部无关连接量线性增长。

## 非目标

- 不建立持久化拓扑汇总表。
- 不延长前端请求超时。
- 不更换 SQLite 或增加第三方依赖。
- 不修改采集、扫描队列或历史保留策略。
- 不改变无目标集群的全局拓扑内部调用行为。
