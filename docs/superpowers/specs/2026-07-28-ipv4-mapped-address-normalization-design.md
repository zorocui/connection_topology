# IPv4-mapped IPv6 地址归一化设计

## 问题

同一对端可能同时以 `10.160.79.21` 和 `::ffff:10.160.79.21` 出现在采集结果中。
后者是 IPv4-mapped IPv6 表示，当前系统按原字符串分组，因而生成两个拓扑节点，
并可能在快照差异中产生错误的新增或删除记录。

## 归一化规则

新增一个采集器和拓扑服务共用的纯函数：

```python
normalize_ip_address(address: str | None) -> str | None
```

规则如下：

- `None` 保持为 `None`。
- 去除 IPv6 区域标识，例如 `fe80::1%eth0` 变为 `fe80::1`。
- 使用 `ipaddress.ip_address()` 规范普通 IPv4 和 IPv6 文本。
- IPv6 地址存在 `ipv4_mapped` 时转换为普通 IPv4：
  `::ffff:10.160.79.21` 变为 `10.160.79.21`。
- 非 IP 字符串保持原值，避免解析异常阻断采集。

地址族由归一化后的地址计算，因此 IPv4-mapped IPv6 记录标记为 `ipv4`，普通
IPv6 仍标记为 `ipv6`。

## 写入路径

Linux `ss` 和 Windows PowerShell 采集解析阶段都对本地地址和非空对端地址执行
归一化。新生成的 `ConnectionRecord` 不再保存 IPv4-mapped IPv6 写法。

## 历史数据兼容

不批量修改现有数据库。以下读取路径在分组或比较前执行相同归一化：

- 设备模式拓扑分组。
- 集群模式拓扑设备匹配和外部节点生成。
- 连接详情字典。
- 前后快照差异键。
- 主机地址解析结果。

因此已有快照无需重新采集即可合并重复节点，API 返回的连接详情也显示普通 IPv4。

## 合并行为

当一个快照同时包含两种写法时，它们归入同一对端节点，边上的连接数量为两组记录
数量之和。系统不删除其中任何连接明细，只统一其展示地址。

## 测试

- 公共函数覆盖 IPv4、IPv4-mapped IPv6、普通 IPv6、区域标识和非 IP 字符串。
- Linux 与 Windows 解析器输出普通 IPv4 和正确地址族。
- 设备拓扑把两种写法合并为一个节点。
- 集群拓扑把两种写法匹配到同一受管设备或外部节点。
- 快照差异不把等价地址判断为新增或删除。
- 运行完整静态检查和自动化测试。
